# 编码规范

[规范索引与等级](README.md) · 界面值只来自 [visual.md](visual.md) · 执行命令只在 [acceptance.md](acceptance.md)

原则：保留现有 React → API → Python 领域／Repository／模型网关边界，渐进提升类型、可读性和故障可验证性。格式统一不能替代逻辑正确性。

## CODE-001 · 架构边界（MUST）

| 位置 | 应负责 | 不应负责／反例 |
| --- | --- | --- |
| `apps/web/src/components/`、`render.ts`、`selection.ts` | 展示、局部输入、可访问交互、源文本映射 | 组件直接访问数据库、持久化整个工作区 |
| `controller.ts`、`hooks.ts` | 命令协调、草稿、运行态、分页查询缓存与失效 | 复制服务端领域状态机，在 JS 决定持久化分叉／删除 |
| `api.ts`、`services/chat-stream.ts` | 类型化边界、传输、取消与事件校验 | 返回类型断言替代运行时校验 |
| `backend/app/main.py` 等 HTTP 边界 | 认证、Pydantic 校验、状态码、调用应用服务 | 混写大段领域规则或直接泄露上游响应 |
| `backend/app/domain/` | 确定性校验与状态变更、UTF-16 规则 | 依赖 FastAPI、SQLAlchemy、网络或浏览器 |
| `repository.py`、`history_transfer.py` | owner／revision、增量 SQL、事务、迁移兼容与导入导出 | 正常分页绕回全量快照，HTTP 请求持有数据库写事务 |
| `providers/gateway.py`、`chat_stream.py` | 协议适配、流解码、运行上下文与完成持久化协调 | 浏览器持有供应商凭据或自行决定回答落库 |
| `desktop/` | 原生生命周期、资源定位、用户目录、打包与运行时集成 | 从当前工作目录读开发 `.env` 作为发布配置 |

新增能力沿既有边界扩展；不要为同一状态另建第二份事实源。当前 domain 兼容路径可操作全量状态，但正常 UI 的新增请求不得因此转回全量。验收：QA-005～QA-007。

## CODE-002 · TypeScript、React 与 CSS（MUST；工具接入为计划）

- TS 保持 strict；公共边界定义明确输入／输出，未知数据先 `unknown` 再收窄。禁止无说明的 `any`、非空断言和 `as` 掩盖协议风险。
- 目标格式：2 空格、单引号、分号、`printWidth:100`、UTF-8、LF；JSX 属性用双引号。长 JSX 按属性／结构展开，不把组件和多个状态声明压成一行。
- 组件与类型 PascalCase，hook 以 `use` 开头，变量函数 camelCase，常量 UPPER_SNAKE_CASE；保留现有 `.js` ESM 导入写法。现有文件不为统一大小写无关重命名。
- 列表用稳定业务 ID 作 key，不用页内 index。可推导值直接计算；编辑草稿才维护独立副本，并明确保存基线与 dirty。
- effect 依赖真实、订阅／定时器／RAF／网络清理成对；异步结果用 generation 或请求身份校验，不能只凭组件仍 mounted 就接受过期结果。
- 命令防重同时考虑同步 guard 和界面 busy；`finally` 恢复状态。错误不能只写 console 后让用户等待。
- CSS 目标每条声明一行，按布局→盒模型→文字→颜色→状态分组；使用 VIS token，避免无说明高 specificity、重复覆盖和大范围 `!important`。
- 动态选区坐标可 inline style；静态尺寸不得散落 JSX。Markdown／原文 HTML 必须经过既有清洗或转义边界，不能把用户内容直接插入 HTML。

Alloy 的职责分离作为目标：Prettier 管格式，ESLint 管逻辑／React 质量；两者不配置相互矛盾的格式规则。**当前没有这两个工具的项目依赖或执行入口**；类型检查、构建成功不等于 lint 已通过。

正例：`key={entry.id}`，只失效受影响分支的查询；反例：每次渲染复制 workspace 到 state，再用 effect 同步回去。验收：QA-005、QA-008。

## CODE-003 · Python 与文本坐标（MUST）

- Python 遵循 PEP 8、4 空格；目标 Ruff format 行宽 100，使用格式器默认引号策略。公共函数、服务／仓储／协议边界补参数和返回类型；局部推导无需机械注释。
- 导入分标准库、第三方、本地；每个 import 清楚展开，避免 `import copy, re, uuid`。不用分号串联语句、单行 class／except 或复杂单行条件隐藏流程。
- 明确异常类型；广泛 `except Exception` 仅在 HTTP、网关、桌面启动等隔离边界兜底，并返回安全错误。取消异常继续传播，资源清理放 finally／上下文管理器。
- 诊断日志 SHOULD 保留异常类型、调用栈、请求／run ID；输出前脱敏，不记录请求体、密钥、完整聊天正文或上游含凭据 URL。不能将异常原文直接返回用户。
- 文本范围统一 **UTF-16 code unit、左闭右开 `[start,end)`**；满足整数、非负、start < end、不越源长度、不拆代理对，必要时核对传入选区文本与源切片相同。
- Python 必须使用 `domain/utf16.py` 的 UTF-16 helper；不能用普通 `text[start:end]` 模拟 JS 偏移。继承片段的源 range 要累加原偏移；不能丢失源坐标。

正例：`A😀中` 中 emoji 占两个 UTF-16 单元，完整 emoji 的范围可引用、半个代理对拒绝；反例：按 Python 字符数切错后悄悄扩大成全文。验收：QA-005。

Ruff 已列入 `backend[test]`，但尚未配置这里的格式目标；mypy 未声明。现有压缩写法作为治理差距，按修改模块整理并单独审查 diff，不要求借功能迭代全仓重排。

## CODE-004 · API 与模型协议（MUST）

边界采用可判别的 action／event 类型，统一字段名、可空语义、单位和错误结构。HTTP 用 Pydantic 明确未知字段与类型转换政策：新协议默认拒绝未知字段；需兼容的字段显式列出并测试。当前 `Action.extra='allow'` 及部分普通 `int`／dict 是差距，不能声称已经全量 strict。

| 契约 | 约束 |
| --- | --- |
| 配置 `timeoutMs` | 整数 100～600000；UI 当前默认 60000，单位毫秒 |
| `maxTokens` | 整数 1～65536；默认 4096 |
| `temperature` | null 或有限数 0～1；当前 UI 步长 0.1，不将其误称服务端只接受一位小数 |
| 模型／地址／密钥长度 | 模型最多 200、Base URL 最多 2048、key 最多 4096；空白有效性另行校验 |
| 写命令 | 校验当前 owner 及命令作用域内合法版本，过期返回冲突、不静默覆盖；现有命令使用工作区 revision，目标图移除／恢复按 CODE-012 校验目标与依赖版本 |
| 流事件 | `started/delta/usage/completed/failed/cancelled`；同 runId，seq 为合法递增整数；未知类型或非法字段按协议错误处理 |
| 完成结果 | backend 成功持久化后发 compact 结果；客户端 EOF、usage 或 partial 不能替代 completed |

适配器使用 `ADAPTERS` 注册表；OpenAI、Anthropic、Gemini 分别编码请求和解析真实文本事件。品牌兼容预设仍走原协议，不能克隆一份仅更换品牌名的网关。

SSE 必须处理分片 UTF-8、CR／LF、事件边界、超时和明确终止语义；不同厂商 finish reason、拒绝／截断与 usage 合并独立测试。停止取消到具体 run，释放 HTTP 和 reader；完成前再次校验 owner、run、上下文签名。正例：只有合法终态才能写一次回答；反例：网络断开仍保存 partial 为成功。验收：QA-005。

## CODE-005 · 数据与资源预算（MUST）

下表是现有主要上限及其单位，新增能力必须保持或显式变更契约；**计数有界不代表任意正文下字节或 RSS 有界**。

| 对象 | 上限／方法 | 当前入口 |
| --- | --- | --- |
| 主题、消息、来源、上下文、引用候选页 | 每页最多 40 条；持久消息 DOM 每页最多 40 行，临时 stream 节点另计 | API／Pager／MessageViewport |
| 消息查询缓存 | 总计最多 8 页，每分支最多 3 页，LRU | `controller.ts` QueryCache |
| 引用显式选择 | 最多 100 个 ID | API／ReferencesDialog |
| 默认全选背景 | scope + 最多 200 个排除 ID；服务端迭代 | SelectionDialog／domain／repository |
| 模型上下文 | 最近最多 100 条、合计 64000 字符；必需选区和最新问题保留，超预算拒绝 | `repository.py` context |
| 前端同时运行 | 最多 3 个主题 | controller |
| NDJSON | 单记录 1 MiB；总文件 2 GiB；磁盘暂存 | history_transfer |
| 旧 JSON／快照兼容路径 | 8 MiB 预算；不供正常 UI 读取全量历史 | repository／request_limits |
| 上游 SSE 防护 | 单行 256 KiB、单事件 512 KiB、总响应 8 MiB、文本 100000 UTF-8 字节 | gateway 常量 |
| 客户端流防护 | 事件缓冲 1 Mi UTF-16 单元；临时回答 256000 UTF-16 单元 | chat-stream／controller |

服务端上下文“字符”按当前 Python 字符计数；不可与 token、UTF-8 字节或 UTF-16 偏移互换。不同层防护不相同且不构成同一输出承诺，服务端更早拒绝时客户端正确呈现失败。

不得因翻页、切主题或运行完成积累无界数据副本；正常 UI 不调用 snapshot。性能 fixture 与通过阈值只在 QA-006 定义。现有元数据全量路径与较长复制事务应持续收敛，不能宣称任意规模已验证。

## CODE-006 · 数据库与迁移（MUST）

- 所有 SQL 读写限定 owner；ID 不是授权证明。使用参数化 SQL／SQLAlchemy，不拼接用户输入。
- 写入与对应作用域的 revision／目标版本检查在同一事务；失败整体回滚，逐操作恢复作用域见 CODE-012。需要唯一性或重复引用防护时在正确并发边界检查，不能只靠按钮禁用。
- 迁移使用新增 Alembic revision，不编辑已发布迁移；优先 additive，破坏性变更先设计备份与迁移路径。旧 JSON 字段仅为迁移时备份，不作为新数据来源。
- 模型网络请求不持有数据库写事务；完成后短事务校验并保存。复制类长事务需测量、说明锁影响，不把尚未优化描述为已分批完成。
- 大文件导入逐记录校验、磁盘 staging、可取消清理，最终原子替换；断开、磁盘满、错误尾记录、revision 冲突时原工作区完整。
- 当前服务单进程单实例 SQLite；新增并发／部署方式须先验证运行态和存储边界，不默认为多节点安全。

正例：另一个 owner 请求来源 ID 被拒绝，且没有部分写入；反例：import 校验到一半已经清空旧库。验收：QA-005、QA-007。

## CODE-007 · 安全与本地数据（MUST）

模型调用只经后端；key 加密保存，读 API、历史导出、日志和前端持久存储均不包含它。只提交同源 API，遵守现有 Cookie／origin 控制。URL 校验、调用前解析、私网策略和禁止重定向保持一致，禁止依靠前端校验替代后端限制。

Markdown 渲染、链接和原文恢复保留清洗／转义；测试恶意 HTML、脚本 URL 与特殊字符。配置和测试 fixture 使用虚构 key；不硬编码真实凭据、生产 DB 或用户 browser-profile 路径。

桌面数据用既定 LOCALAPPDATA 路径，密钥用 DPAPI 保护；发布程序不依赖 CWD／PYTHONPATH。升级、卸载和测试不删除真实用户数据。正常发布不开调试端口。正例：隔离 profile 验证重启；反例：使用开发者常用数据库跑破坏性测试。验收：QA-005、QA-007。

## CODE-008 · 测试代码（MUST）

测试验证可观察行为和持久化不变量：domain 测状态与坐标；repository 测 owner／revision／回滚；gateway 用协议特定 fixture；浏览器测真实操作、焦点和竞态；桌面测实际打包资源与身份持久化。

异步测试等待具体元素、状态或响应，不靠任意长 sleep；模拟慢响应、失败与乱序应可控制、可重复。使用临时数据库和独立 profile，结束清理进程与连接。快照不能代替数据正确性断言，测试数量不能代替覆盖说明。

正例：模拟草稿写失败后点击另一主题，断言当前主题和输入都未变化；反例：只断言函数调用次数。已有入口与计划工具见 QA-008。

## CODE-009 · 可审查变更（MUST）

改动应以一个可验证目标组织，列出适用规则、兼容性、数据影响和对应测试。新增错误恢复路径同时更新交互说明；改契约同时更新两端类型与测试。注释解释原因／约束，不重复语句字面意义。

保持 intended files 的增量范围；格式整理与业务改动可区分，不借工具自动修复覆盖用户工作。需要提交时只提交本次文件，不含密钥、数据库、日志、profile 或生成包；是否 commit 由用户任务授权决定。

## CODE-010 · 依赖与参考实现（MUST）

Python 运行依赖及 test／desktop／desktop-test extras 在 `backend/pyproject.toml` 声明；npm 依赖在对应 package 中声明并同步现有 `package-lock.json`。不要假定已有 Python lock 文件，或把本机全局安装当可复现依赖。

新增依赖说明用途、维护状态、许可证、体积与发布兼容性；优先现有能力，禁止为一次格式整理无说明引入整套工具。腾讯公开指南可借鉴原则，不直接复制未核对许可的代码／字体／资源。涉及 AGPL 等参考项目时保持独立实现，具体复制或链接必须先核对许可义务，不能将“未复制”写成未经调查的结论。

验收：QA-008、QA-009；依赖安装和配置落地另开实施范围，本规范不代表已经引入工具。

## CODE-011 · 原生图投影、查询与视图状态（MUST，图形迭代目标）

图是现有服务端 domain／Repository 数据的唯一事实源投影；Web 渲染器仅维护有界查询结果、临时交互和镜头。复用主题／branch、message／entry、来源和引用的稳定 ID，不导入独立 MindMap 数据库，不复制 MindFlow domain，不引入 PySide UI 或第二后端。渲染技术选型不改变该边界。

### 语义与写入

- 产品对象定义唯一见 INT-011。parent 森林无环、每节点至多一个 parent，服务端在同一事务内校验 owner、目标存在、revision 和环；不能仅对客户端当前加载片段查环。多个根保持真实独立，布局不得伪造 parent。
- 跨边为显式可判别类型：引用保留方向、稳定出处 ID、UTF-16 range 与既有快照语义；联系独立表达关联。跨边可有多节点环，遍历必须有 visited、深度／数量边界。拒绝自环、非法来源及按类型定义的重复边，不把无向去重套到所有有向引用。
- 现有引用优先从既有记录派生；新的“联系”、归属调整或关系撤销须先设计领域命令和迁移。图中可见边、选中集、位置与折叠集合不得作为上下文构造输入；真正引用／背景配置经现有校验和预算进入模型流程。
- 命令区分位置更新、关系创建／删除、归属调整和主题删除；断线不删除主题／消息，子分支删除语义按 INT-005。持久化位置和关系撤销均是针对已确认版本的补偿命令，不用全图 snapshot 回滚；未知结果先查询实际状态，过期版本返回冲突。

### 状态归属与 schema 目标

| 层 | 内容与写入边界 |
| --- | --- |
| 领域持久化 | 主题、消息、草稿、关系、归属、删除操作记录，由服务端事务管理 |
| 可持久布局偏好 | graphPositions（节点 ID→有限世界坐标）、pinned、布局版本；显式整理提交，独立版本及 owner／workspace 作用域 |
| 当前视图 | camera center／scale、Focus／Peek／Overview、LOD、collapsed、比例、自动展开／锁定偏好；默认会话态，不写工作区 revision |
| 指针运行态 | pointer ID、起点、捕获、阶段、稳定目标 ID、路径／选择预览、冻结原因；客户端临时态 |
| 活动编辑态 | 唯一活动分支 ID、真实编辑器、草稿／保存基线、IME、caret 和阅读锚点；不由镜头派生或重建 |

上述名称为未来字段候选，**现有 schema 未因此扩展**。实施时明确作用域、布局版本、默认值、有效范围、导入导出政策、失效 ID 清理与迁移测试，界面值引用 VIS-012／013。需要跨设备保存视图偏好时单独定义偏好协议与冲突策略，不能把选择、平移、折叠、LOD 或自动镜头保存成业务 mutation。

位置及固定状态由服务端管理独立版本，未持久化不能显示“已保存布局”。世界坐标不保存成 CSS 屏幕坐标；重命名和流式更新保持稳定 ID 及布局，已固定位置只有显式整理／重排才可改变。镜头、LOD、选择集和位置均不进入 AI 上下文，不复制消息事实源。

### 有界投影 API 与资源预算（新增初始目标）

图查询 API 已有 `/api/graph` 有界实现及测试，当前差距见索引；以下仍是完整目标契约，不代表每项已完成。输入为世界视口边界、细节要求、目标／聚合 ID、游标与请求身份；输出 revision、稳定节点 ID、标题／类型、typed edges、原文摘录定位、聚合数量、实际覆盖范围及后续游标。概览在服务端聚合，不先下载全量 positions；正文仍用现有分页接口。

| 对象 | 初始预算与方法 |
| --- | --- |
| 单次图响应 | 最多 200 个节点／聚合、400 条边；解压 UTF-8 body ≤256 KiB，按语义完整项减少预览并分页 |
| 当前画布挂载 | 最多 200 个可操作节点／聚合、400 条边、60 个可见标题标签，L2 最多 12 张；胶囊标题计入标签预算，按 VIS-013 优先级保留 |
| 原文摘录 | 每节点最多 2 段，每段最多 120 个 Unicode code point；保留 UTF-16 源 range 与消息版本，不拆代理对；字节上限独立校验 |
| 图查询缓存 | 最多 4 个窗口、800 个节点投影、1600 条边；摘录附属于有界投影，不用完整消息代替摘录 |
| 完整阅读 | 仅活动 L3 使用 CODE-005 消息页／缓存上限，stream 另计；不为邻居拉取全量历史 |
| 可访问列表／最近移除列表 | 每页复用 CODE-005 最多 40 项，搜索／分页访问未加载分支；恢复列表不一次回读删除正文 |

缓存按 owner／workspace／revision／查询身份隔离、LRU 淘汰，摘录版本变化只失效对应项。消息增多先降 L1／L0，不增加图预算或缩字；选中集用稳定 ID 表达，超出显示预算用有界列表检查，仅明确提交的目标进入领域命令。

连续镜头合并查询、取消无用请求并拒绝迟到响应；过渡优先用已有投影，LOD 升档按需有界加载，慢网络显示占位／重试。避免每帧网络请求、全局组件重渲染或全图布局；后台完成只失效相关分页／摘录。窗口外端点用导航指示，不虚构节点归属；活动节点离屏保留状态和聚焦入口。命中及碰撞按有界结果计算。预算是目标而非成绩，证据见 QA-010。

## CODE-012 · 手势状态机与逐操作恢复（MUST，图形迭代目标）

### 输入仲裁

至少区分 idle、pressCandidate、pan、lasso、connectPreview、movePreview、erasePreview、submitting、resultUnknown。每个 pointer 会话至多一个动作解释器，文本编辑／原生选区优先；时间和距离采用 VIS-014，使用单调时钟与 CSS 坐标。

识别后 pointer capture，冻结自动镜头与命中布局；手势期间关闭边缘自动平移，避免目标移动。路径按相邻采样点线段求交，可合并共线样本，采样点数与生命周期有界。候选按首次交点判定，歧义不提交；锁定后用 stable ID，而非列表索引或当前活动 ID。

Escape、取消按钮、window blur、pointercancel、capture loss 清理预览／定时器／捕获；已 submitting 转结果核实。contextmenu 兼容 Chrome／WebView2 事件顺序，只局部处理当前图手势，输入保留原生菜单；右键按下不能删除。

### 删除收据与事务：目标契约（已有部分 API，验证差距见索引）

候选收据字段为 `operationId`、`ownerId`、`workspaceId`、操作类型、稳定目标 ID 集、目标预期版本、`committedAt`、`expiresAt`、状态及恢复内容引用。时间由服务端生成；客户端重试沿用同一幂等 operation ID。查询／恢复均校验 owner，ID 本身不是授权。

tombstone 保存该操作拥有的主题、持久消息、已确认草稿、原归属及关系恢复资料／依赖版本，不保存整个工作区快照。多选移除限定明确目标集、原子提交；正式 API 必须定义数量及请求字节上限，超限说明可分批操作，不能静默只删一部分。

事务流程：校验 owner／目标版本→协调对应 run 终态并阻止迟到落库→保存 dirty 草稿及恢复内容→软移除目标并保留／脱离独立子分支→生成持久收据及有效活动对象→确认。模型网络等待不持有写事务；最终事务重新检查目标版本、run 身份及是否有新运行。失败整体回滚，不以本地预测报告成功。

回答刚完成时可在最终一致版本上重试移除并纳入该回答；已取消则拒绝迟到成功写入。移除期间目标不能创建新 run，其他分支不受影响。恢复不宣称持久化未保存 partial，也不重启模型。

### 恢复与冲突

- 以 operation ID 和需要的目标／依赖版本恢复，事务校验 owner、服务器期限、状态、ID 占用和关系前置条件。工作区 revision 可用于观测及缓存失效，无关 revision 变化不能作为唯一拒绝原因；期限唯一见 INT-005。
- 重复恢复返回同一已恢复结果，不重复插入；结果未知可查询。已移除／已恢复只在持久状态确定后显示。
- 普通选择、镜头、其他草稿／run／阅读不使记录失效。恢复对象或依赖确有冲突时返回结构化原因，原子失败保留未过期记录，无局部覆盖。
- “作为独立根恢复”等降级方案须预览确认，再以新补偿意图提交，关联原操作；只补偿该操作，不恢复旧全局 revision 或回滚其他对象后续内容。
- 删除、恢复、永久操作与到期清理在事务中协调，同一记录至多一次有效恢复；到期拒绝恢复，清理延迟不延长承诺。
- 恢复布局可约束到当前可见空间，但不覆盖后续用户布局；恢复不自动切换活动分支或发送。返回稳定 ID 供局部失效及高亮。

图手势与主题菜单共同迁移到该契约，包含收据查询、刷新恢复和旧端点隔离。现有 next-mutation undo 仍按 INT-005 说明当前限制，不能用来兑现新图逐操作恢复。验收：QA-004、QA-005、QA-010。
